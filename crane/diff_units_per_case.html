WMS Solution Design - Multiple Units Per Case Per Pallet

1. Business Requirement

The warehouse management system (WMS) needs to support scenarios where a single serialized SKU can have different Units Per Case (UPC) values within the same pallet.

Currently, the PALLET_DTL table uses the following logical key:

Primary Key: PALLET_ID + SKU

Since the SKU is serialized, multiple case configurations can exist for the same SKU on a pallet. This creates a challenge because PALLET_DTL can store only one Units Per Case value at the SKU level.

2. Design Options Evaluated

Option 1 – Manage Variable Units Per Case at Serial Number Level

Continue using the existing PALLET_DTL structure without modifying its primary key.

In this approach:

  • PALLET_DTL remains keyed by PALLET_ID + SKU.
  • Units Per Case in PALLET_DTL represents the standard SKU-level value.
  • The actual quantity contained in each serialized case is maintained in the Case Serial Number inventory table.
  • The On-Hand Quantity maintained against each case serial number represents the actual Units Per Case for that specific case.
  • Operational processes derive the case quantity from the serial-level inventory record whenever required.
Example:
  • SKU: SKU1001
  • PALLET_DTL Units Per Case = 24
  • Case Serial A → On-Hand Qty = 24
  • Case Serial B → On-Hand Qty = 12
  • Case Serial C → On-Hand Qty = 18
Although PALLET_DTL contains a standard value, the actual case quantity is obtained from the corresponding serialized inventory record.

Option 2 – Introduce Case-Level LPN Hierarchy

Treat each physical case as an independent LPN.

In this approach:

  • Every case receives its own LPN.
  • A new "Master LPN" represents the physical pallet.
  • Case LPNs are mapped to the Master LPN.
  • The pallet becomes a parent-child LPN structure.

While this approach provides greater flexibility, it introduces significant system changes.

Process Area Impact
Receiving Additional LPN creation and association logic
Inventory Management Master/Child LPN maintenance
Cycle Counting Changes required to count and reconcile hierarchical LPNs
Picking Updates needed to support child LPN selection
Replenishment Enhanced handling for nested LPN structures
Inquiry Screens UI enhancements required to display hierarchy

3. Solution Evaluation

Criteria Option 1 Option 2
Database Changes Minimal High
Impact on Existing Processes Low High
Cycle Count Changes None / Minimal Significant
Picking Changes Minimal Significant
Implementation Risk Low High
Time to Deliver Short Long

4. Final Decision

Approved Solution: Option 1

The team agreed to proceed with Option 1, where PALLET_DTL continues to maintain the SKU-level Units Per Case information and the actual case quantity is managed in the serialized case inventory records.

The On-Hand Quantity stored against each case serial number will represent the actual quantity contained within that case.

This approach satisfies the business requirement while avoiding major changes to existing inventory, cycle count, picking, replenishment, and pallet management processes.

5. Benefits of the Selected Solution

  • Preserves the current PALLET_DTL data model.
  • Avoids introducing LPN hierarchy complexity.
  • Minimizes impact on existing warehouse transactions.
  • Reduces development and testing effort.
  • Supports varying case quantities for serialized SKUs.
  • Provides a lower-risk implementation path.

6. Assumptions

  • Each case is uniquely identified through a case serial number.
  • Case serial inventory records can store the actual On-Hand Quantity.
  • Operational transactions requiring case quantity will reference the serial-level inventory data.
  • PALLET_DTL quantity remains aggregated at SKU level.
