Shiperoo - Important Queries

Allocation

order_header.ord_sub_status 10 = waiting for allocation; 20 = all lines fully allocated. A status-10 order can hold allocated units on some lines while other lines are short, blocking other orders. Both queries are read-only and assume no free stock; set the company in the params CTE. Click a link to view the query and copy it.

  • Lists status-10 orders whose allocation can be released and held, so waiting orders can fully allocate on the next run.

  • Same logic, summarised: orders to release and hold, units freed, orders expected to complete.

Inventory - expiry consolidation (AutoStore aisle AA)

Consolidates the pallets in aisle AA by warehouse, company, SKU and disposition code onto the pallet that expires first, using a new system transaction EC (Expiry Consolidation: -ve on each source pallet, +ve on the target; not sent to host). All on-hand moves off the source pallets and their loc_pal rows are deleted; preassigned_pick_qty stays on the source as history. These scripts change data: run 01 first, then 02. 02 backs up pallet_hdr, pallet_dtl and loc_pal first and ends in ROLLBACK by default; change it to COMMIT once the checks look right. Scoped to warehouse FC (set in ec_params). Click a link to view the script and copy it.

  • Adds EC to trans_codes (system trans = Y) and trans_cd_gl for each company with send_to_host = N, cloned from PC.

  • Previews the move, writes the EC inv_transaction legs, updates pallet_dtl, deletes emptied source pallets from loc_pal.

  • Backs up seq 100 and 111, then updates gen_upl_pre_post_data_setup: seq 100 sums the EL rows (SKU + expiry) to one row per SKU on load, seq 111 gets WMS aisle AA on-hand by SKU. Lot and expiry are not compared.

  • Replaces the expiry-matching PL/pgSQL loop with a set-based update that sums aisle AA on-hand by company and SKU only.
