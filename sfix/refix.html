1 Business Background

Orders are picked from the warehouse floor and consolidated into a tote. During the packing stage, an order may be split across multiple physical cartons. Each carton is uniquely identified by a Shipment Container Number (SCN).

  • One order can have one or more SCNs.
  • Packing includes a full SKU audit to verify contents against the order.
  • Discrepancies discovered during packing trigger the REFIX process.

2 Packing Audit Process

The packer performs a full SKU-level audit for every SCN before the carton is closed. An SCN is flagged for REFIX when any of the following conditions is detected:

  • A SKU is missing from the carton.
  • A SKU is present but damaged.
  • A SKU was not picked at all.
  • The quantity of a SKU does not match the order demand.

When flagged, the SCN is assigned 10 – REFIX_REQUIRED and enters the REFIX workflow.

3 REFIX Process Overview

The REFIX coordinator reviews the flagged SCN and determines whether the missing inventory can be sourced from the warehouse.

Path A – Inventory Found

  • The missing SKU is added directly to the SCN.
  • The SCN is dispatched to QC/Packing for re-audit.
  • Status set to 20 – QC_PENDING.

Path B – Inventory Not Found

A warehouse inventory check is performed:

  • Inventory available → A putwall and position are assigned; status becomes 30 – REPICK_REQUIRED.
  • Inventory unavailable → The SCN is sent for restyling via ERP; status becomes 50 – RESTYLING_REQUIRED.

4 Restyling (ERP Order Revision)

When inventory cannot be sourced, the order is sent to the ERP system for revision ("restyling"). ERP may perform any combination of the following changes:

  • Remove order lines entirely.
  • Reduce line quantities.
  • Increase line quantities.
  • Add new order lines.
  • Replace SKUs with alternatives.

The WMS receives the revised order and applies all changes systematically.

5 Multi-SCN Orders

Current Assumption ERP revisions affect only the SCN currently under REFIX processing. Handling of revisions that impact inventory already packed in a different SCN on the same order is addressed under Future Enhancements.

6 SCN Table – Schema Changes

Three new columns are added to the SCN table to support the REFIX workflow:

Column Type Purpose
REFIX_STATUS INTEGER / VARCHAR Tracks the current REFIX stage for the SCN (see Status Model).
PUTWALL_ID VARCHAR Identifies the putwall the SCN is assigned to for repicking.
PUTWALL_POSITION VARCHAR Identifies the specific position within the putwall for this SCN.

9 Restyling Receipt Processing

When the WMS receives a revised order from ERP, the following steps are executed systematically:

  1. Receive the revised order payload from ERP.
  2. Generate a REVISION_NO for the revision event.
  3. Compare the current order lines against the revised order lines.
  4. Identify all changes: removals, quantity reductions, quantity increases, and new line additions.
  5. Execute CPICK transactions for excess quantities.
  6. Create cancel detail records in I_IMPL_SFX_REFIX_CANCEL_DTL.
  7. Update ORDER_DETAIL with revised quantities and line statuses.
  8. Insert new order lines where applicable.
  9. Update demand in ORDER_GROUP_DTL.
  10. Update demand in WORK_GROUP2_DTL.
  11. Set the SCN status to 70 – RESTYLING_RECEIVED.

10 CPICK Processing

Excess quantities (arising from quantity reductions or line removals in the revised order) are systematically CPICKed and moved to CPICK inventory. This ensures warehouse inventory records are accurate after the restyling revision is applied.

Key Point CPICK processing is fully automated as part of restyling receipt — no manual operator intervention is required at this stage.

11 Cancel Detail Table – I_IMPL_SFX_REFIX_CANCEL_DTL

This table tracks items that must be physically removed from an SCN after a restyling revision. It is created and populated automatically as part of the Order Revision Updates processing step — records are inserted by the system when a restyling revision is received and compared against the current order.

12 Order & Demand Updates

ORDER_DETAIL

  • The existing ORD_QTY is preserved in ORIGINAL_ORD_QTY before any revision.
  • ORD_QTY is updated to reflect the revised value from ERP.

Demand Regeneration

Revised demand is propagated to both downstream demand tables:

  • ORDER_GROUP_DTL
  • WORK_GROUP2_DTL

13 RESTYLING_RECEIVED – Operator Workflow

Once an SCN reaches status 70 – RESTYLING_RECEIVED, the operator follows these steps:

  1. Scan the SCN barcode.
  2. The system displays two lists:
    • Pending Removals — items to physically remove (sourced from I_IMPL_SFX_REFIX_CANCEL_DTL).
    • Pending SKU Demand — new or increased SKU quantities required (sourced from WORK_GROUP2_DTL).
  3. Operator removes each listed item from the SCN and confirms each removal in the system.
  4. System marks confirmed items as USER_REMOVED in I_IMPL_SFX_REFIX_CANCEL_DTL.
Validation Rule All pending removals must be confirmed by the operator before Putwall assignment is permitted.

14 Putwall Assignment

After all physical removals are confirmed, the operator assigns the SCN to a putwall:

  1. Enter PUTWALL_ID.
  2. Enter PUTWALL_POSITION.
  3. System validates that no pending removals remain.
  4. SCN status is set to 30 – REPICK_REQUIRED.
Design Rule One putwall position accommodates exactly one SCN at a time.

15 Batch Pick Creation

Batch pick tasks are created to source the repick inventory for REFIX SCNs:

  1. Retrieve all SCNs with status 30 – REPICK_REQUIRED.
  2. Filter by target Putwall.
  3. Retrieve the associated orders for the filtered SCNs.
  4. Read pending SKU demand from WORK_GROUP2_DTL.
  5. Consolidate SKU demand across all orders for the putwall.
  6. Create the Batch Pick Task in the WMS.
  7. Update each SCN status to 40 – REPICK_TASK_CREATED.

16 Inventory Allocation Strategy

Inventory is not reserved or pre-allocated at either the putwall assignment or batch pick creation stages.

Allocation Timing Inventory is allocated only during Putwall Distribution.

Allocation priority is applied in the following order:

  1. Ship Date (earliest first)
  2. Order Priority

17 Putwall Distribution

The picker fulfils the batch pick and distributes inventory to putwall positions:

  1. Scan Putwall ID.
  2. Scan Cart.
  3. Scan each SKU from the cart.
  4. System suggests the correct putwall position for the scanned SKU.
  5. Operator scans the SCN to confirm placement into the suggested position.

When all inventory in the cart has been distributed, all related SCNs are automatically advanced to 20 – QC_PENDING.

18 Short Pick Handling

There is no special exception handling for short picks in the REFIX workflow. Available inventory is distributed according to the standard allocation priority (Ship Date → Order Priority). SCNs that did not receive all required units will re-enter the packing audit and may re-enter the REFIX cycle.

19 Return to QC

Once an SCN is in status 20 – QC_PENDING, it is routed back to the packing/QC station. The packer performs a full SKU audit.

  • If the audit passes, the carton is closed and dispatched normally.
  • If the audit fails, the SCN re-enters the REFIX process from status 10 – REFIX_REQUIRED.

20 Design Assumptions

#Assumption
1One putwall position holds exactly one SCN at any given time.
2Only one active cart per putwall cycle is permitted.
3Packing always performs a full SKU audit (no partial audits).
4The WMS is responsible for generating and managing revision numbers; ERP does not provide them.
5PUTWALL_ID and PUTWALL_POSITION columns remain populated after putwall completion (not cleared).
6ERP revisions currently affect only the SCN under active REFIX processing.

21 Implementation Tasks

The following 14 API development tasks have been identified. All deliverables are back-end API and service implementations; no UI components are in scope for this phase.

# Task Description
1 SCN Schema Changes Add REFIX_STATUS, PUTWALL_ID, and PUTWALL_POSITION columns to the SCN table. Deliver cross-vendor migration scripts (MSSQL, PostgreSQL, Oracle) with appropriate indexes.
2 REFIX Status Framework Implement the 7-state REFIX lifecycle (codes 10–70) in the WMS engine. Enforce valid state-transition rules and expose status-change service APIs.
3 ERP Integration Build the inbound integration to receive revised order payloads from ERP (restyling responses). Handle message parsing, acknowledgements, error responses, and retry logic.
4 Restyling Comparison Engine Implement the diff engine that compares current order lines against the ERP-revised order. Identify line removals, quantity reductions, increases, and new additions. Generate REVISION_NO.
5 CPICK Processing Automate CPICK transactions for excess quantities identified during restyling comparison. Update WMS inventory records to reflect quantities removed from demand.
6 Order Revision Updates On restyling receipt: copy ORD_QTY → ORIGINAL_ORD_QTY, apply revised quantities to ORDER_DETAIL, insert new lines, and mark removed lines as cancelled. Create the I_IMPL_SFX_REFIX_CANCEL_DTL table and populate cancel detail records as part of this processing step.
7 Demand Regeneration Propagate revised order demand from ORDER_DETAIL downstream to ORDER_GROUP_DTL and WORK_GROUP2_DTL after each revision is applied.
8 Putwall Assignment API Implement the putwall assignment business logic and API. Validate that all pending removals are confirmed before allowing assignment. Persist PUTWALL_ID, PUTWALL_POSITION, and advance the SCN to REPICK_REQUIRED.
9 Batch Pick Creation API Aggregate REPICK_REQUIRED SCNs by putwall, consolidate SKU demand from WORK_GROUP2_DTL, create a Batch Pick Task in the WMS, and advance each SCN to REPICK_TASK_CREATED.
10 Batch Picking API Implement the pick-execution API that processes individual pick confirmations during a batch pick task. Update pick task line statuses, record inventory movements, and close the task when all lines are fulfilled.
11 Putwall Distribution API Implement the scan-driven distribution API: validate SKU-to-position mapping, record inventory placement against the SCN, and automatically advance all related SCNs to QC_PENDING when the cart is fully distributed.
12 Allocation Logic Implement late-binding inventory allocation at putwall distribution time. Apply priority rules (Ship Date → Order Priority). No inventory reservation at wall assignment or task creation stages.
13 QC Integration Integrate REFIX status with the QC/Packing audit workflow. Route QC_PENDING SCNs to the packing station. Reset SCN to REFIX_REQUIRED when the audit fails.
14 Exception Handling Implement error handling across all REFIX workflow transitions: ERP communication failures, invalid status transitions, missing inventory records, and concurrent modification guards.
Target Delivery All 14 tasks are targeted for delivery by August 17, 2026.

22 Future Enhancements

Multi-SCN Revision Impact Handling

The current design assumes ERP revisions affect only the SCN currently being processed by REFIX. A future enhancement will address scenarios where a restyling revision impacts SKUs that are physically packed in a different SCN on the same order. This requires cross-SCN inventory reconciliation logic and is planned for a subsequent release.
